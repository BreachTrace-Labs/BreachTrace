# Research risk register and critical reviews

Probability and impact are qualitative planning judgments. A trigger identifies when to narrow or withdraw a claim.

| Risk (likelihood/impact) | Trigger or diagnostic | Mitigation, owner and residual uncertainty |
|---|---|---|
| Integration mistaken for novelty (high/high) | Equal native query matches every exact-key decision | Research lead emphasizes stage-wise evidence loss and identifiability; claim algorithmic improvement only on an independent fair comparison. Prior art search remains open. |
| No independent native action ledger (high/high) | Only screenshots, historic row totals or test fixtures available | Data custodian requests sanitized receipts and matching native records. Downgrade to replay semantics when absent. Consenting owners may be atypical. |
| Circular identity ground truth (high/high) | Target key label derived from the same field the baseline tests | Separate true operator alias and observable field justification. Blind annotators and hide event-generator markers. Some historical events remain unresolved. |
| Shared-principal/actor confusion (high/high) | Routine target use or sibling key counted as malicious | Use mixed and indistinguishable controls. Score credential, success and intent separately. Actual actor intent often unrecoverable. |
| Coverage selection and censoring (high/high) | Only returned or successfully parsed records included | Independent action denominator; native export digest, cutoff, unavailable source states and all-assigned analysis. Native export itself may omit operations. |
| End-bound and outcome divergence (high/high) | Dynamic summary and persisted report operate on different event sets | Score both with matched scenarios and scope-aware rubric. Document legitimate account context; freeze version and time. Old reports may survive refresh. |
| Synthetic realism and representativeness (high/high) | Provider fields populated artificially for all cases | Native, example and synthetic strata; preserve real missingness; publish distributions and data rights. No extrapolation to providers without samples. |
| Leakage and pseudoreplication (high/high) | Same key, template, repository, account or export across splits; rows treated as N | Partition related groups together, cluster uncertainty and report sites. If too few independent sites, restrict conclusion to sampled sites. |
| Reader access, retention and cost (high/medium) | Azure Graph denied, Twilio rejected, AWS/GCP/Stripe lack verified readers in historical check | Use authorized exports; record scope, dates, page caps and currency-specific costs. No expanding permissions or creating services implicitly. Missing mode remains blocked. |
| Redaction changes identifiability (medium/high) | Different identifiers alias together, or key resource loses required shape | Custodian validates keyed pseudonyms, equality/format invariants and pre/post redaction field masks. Raw data stays restricted. Some sources cannot be released. |
| Secrets or personal data enter artifacts (medium/high) | Raw log body, credential, phone, IP, resource name or sensitive prompt reaches public output | Release allowlist and independent review; dedicated dummy identities, local model path, least-privilege access, retention deadline. Keep private crosswalk separate. Derived data may remain identifying. |
| Missing timestamps or provider delays (high/medium) | Negative elapsed times, query before ingestion or serial polling | Separate event, arrival, clock-domain and collection times. Interval censor; isolate network/runtime. Historical data cannot establish end-to-end latency. |
| Weak or unfair baselines (medium/high) | Competitor lacks original file path, native query loses field unavailable to BT, model gets unequal information | Equal-input table and matched intersection plus all-assigned set. Distinguish privileged upper bound. Paid product head-to-head can remain unavailable. |
| LLM adjudication and nondeterminism (high/medium) | Validator passes unsupported factual inference, fallback mistaken for model success | Independent atom-level review, repeat per case, pin digest/config, separate first attempt and delivered report. Model revisions limit transfer. |
| Inadequate power/multiple outcomes (high/high) | Sample counts dominated by repeated events; selective reporting | Seal hypotheses and practical margins, analyze paired cluster effects, disclose all arms, adjust secondary families, mark inconclusive. Rare severe error bounds can remain wide. |
| Unreliable incident replay (medium/high) | Fixtures bypass collector mapping/queue/API and get labelled end-to-end | Record injection boundary per run and actual serializer/surface. Use replay for processing and record provider acquisition separately. No replay-to-live speed extrapolation. |
| Schema/map or version drift (medium/medium) | Prompt v1 pilot mixed with v4, ignored results missing from clone | Hash code, settings and separate local results, preserve provenance. Dead docs and legacy data need separate treatment. |
| Financial, legal or productivity overclaim (medium/high) | Amounts converted to damage, flags to obligations, click counts to saved analyst hours | Report operation amount/currency, heuristic flags and procedure counts only. Independent loss investigation or human study required for broader claims. |
| Ethical scope creep (medium/high) | Study would require publishing a working credential, testing an unrelated account or replaying offensive activity | Data lead substitutes inactive synthetic shapes, benign archived observations and documented examples. Record any resulting external-validity limit. |
| Compute or annotation overrun (medium/medium) | Matrix grows with provider × model × repeats; reviewers cannot double-rate | Prioritize P0 and representative source diversity; cap optional workloads and report omitted cells. Never treat unavailable results as favorable. |

## Three critical reviews and design revisions

**Novelty review.** Credential exposure measurement, cloud event correlation, normalization and LLM reporting all have strong precedents. GitGuardian NHI and native investigation tools directly defeat the alert-only narrative. Revision: center the work on mixed credentials, observable evidence ceilings and propagation of scope. A fair native query can tie or outperform BT and still contribute a useful result. Remove all priority claims.

**Statistical validity review.** A single query returning 140 rows may represent one application and one window. A detector-selected corpus cannot estimate misses outside its candidate pool. A method can eliminate false accusations by saying nothing. Revision: independent action ledgers and truth, separate native/fixture strata, paired case and cluster inference, and a joint error-and-yield decision. The five-point noninferiority margin needs stakeholder agreement before registration. Report underpower and unresolved links.

**Systems feasibility review.** The GCP timeline has more identity information than the scorer explicitly consumes. Azure sign-in authority is separately permissioned. Account-level SaaS events cannot validate every request. Original GCP exports are unverified, and the present pipeline does not establish general exposure closure. Revision: design an offline reproducible core, explicitly grade actual output assertions, distinguish live availability, preserve failed reader checks, and require a second source before a cross-provider empirical conclusion.

**Strongest residual limitations.** Independent native operation truth, sufficient distinct accounts and permission to release corresponding evidence are the limiting resources. If absent, the deliverable remains a defensible benchmark design and controlled demonstration of identifiable versus unidentifiable cases. The existing implementation and pilots alone do not establish publication-level empirical novelty.
