# Experimental protocol for Terra High

**Primary decision.** Can a responder correctly identify activity attributable to a particular credential with fewer wrong-key claims than a principal/time join while retaining useful yield versus a native field-aware query? The strongest negative result would be equal performance to a simple query at the record level and a loss of identity scope in downstream summaries. That result still matters if demonstrated on independent records.

## Shared protocol binding every experiment

1. Freeze code, reader/source modes, baseline implementations, time boundaries, assertion rubric, sampling frame, practical margins and analysis before unlocking held-out truth. Preserve the original measurements listed in the source of truth. Create research-only adapters in a separate workspace. No changes to deployed behavior are prerequisites.
2. Use separately labelled strata: hand-built protocol fixtures, documented vendor example records, and sanitized, owner-provided native record exports paired with independently recorded benign operations. Obtain export provenance, release rights and source/configuration description. Keep sources without independent action ledgers for schema-only analysis. Synthetic fixtures answer mechanism questions. Only independent native bundles can support empirical source-coverage claims. Never pool their rates. No public usable credentials, credential checking, attack enactment or third-party target access.
3. Build four immutable tables. **actions**: case/operation ID, source mode, target/other alias, principal/account alias, intended operation/resource, observed result and trusted interval. **native_records**: scoped opaque ID and file digest, field-presence mask, acquisition and event timestamps, source/mode, log class and pagination/cutoff status. **links**: action ID, native ID, reference matching method and uncertainty. **assertions**: output version/surface, atom, subject scope, predicate, time, resource, modality, cited record IDs and independent adjudication. Keep private crosswalk apart from input. Synthetic identity aliases must preserve equality, inequality and valid structural formats without corresponding to a real secret.
4. Independently register block composition: target-only, same principal/other key only, mixed, unrelated principal or account, zero actions, and activity only outside the interval. Include benign reads, successful benign state changes represented in archives, failed/denied and unknown outcome, with missing and alternate-key identifiers. Balance target/non-target opportunities by construction in fixtures. Preserve and report natural prevalence in archives. Mark unsupported provider cells structural NA. Use negative examples with the same operation, time band and resource as positives to defeat easy shortcuts.
5. Two labelers independently annotate raw records and output atoms, blind to system/variant. Producer truth comes from the ledger, while evidence sufficiency comes from the fields legitimately visible to the method. Hide truth identifiers and artificial labels from system inputs. Resolve disagreements through a third reviewer before unblinding. Report pre-adjudication agreement, Cohen's kappa or weighted kappa for ordered labels, raw agreement and unresolved count. Where labels remain uncertain, give both conservative and optimistic bounds. Freeze matching keys before looking at system errors. Never label from the taxonomy being tested.
6. Group splits by source account/project, originating incident, repeated key alias, export and scenario template. Keep derivatives, swapped worlds and format variants together. Development cases tune only instrumentation and baselines. Dedicated held-out case manifests are digested and sealed. Multiple rows from the same case, five model generations and repeated timings do not create five independent incidents.
7. **Precision planning.** Start with 12 disjoint development cases per available principal source to estimate availability, discordant pairs and within-account correlation. For a binary incident outcome, 97 independent cases give approximate worst-case 95% half-width .10. For paired difference D in {-1,0,1}, variance is discordance minus squared difference. For anticipated discordance .25 and minimal difference .10, approximate two-sided 5%/80% power needs about 196 independent pairs before clustering. Inflate by 1+(m−1)ρ for mean cluster size m and intracluster correlation ρ; add prespecified allowance for missing exports. Derive paired-yield noninferiority sample separately from pilot variance and margin .05, then use larger requirement. Archive simulations/design calculations and freeze final N before held-out data. If unattainable, label results exploratory with intervals. Never top up based on significance. No claim that 30 observations ensure power.
8. Compare methods on identical blinded inputs, eligible time window, action vocabulary, mode and clock budget. Record how unavailable inputs differ. Also give all-assigned/intention-to-evaluate results, with failures as unavailable and lost yield. For conditional precision report only on decided examples with denominators. Treat missing telemetry as potentially informative; stratify and report bounds, avoid blind imputation. Keep timeouts/right censoring. Keep all extreme times unless a documented measurement fault invalidated the clock; show sensitivity with and without invalidated cases.
9. Primary estimates are paired case differences stratified by source, with 95% cluster bootstrap intervals resampling independent source units then incidents (10,000 draws, frozen seed). For few source clusters report individual sites and limit inference to those sites; exact McNemar for independent paired binary outcomes or cluster-level randomization where valid. For the joint primary claim require both endpoints to pass as prespecified. Secondary confirmatory comparisons use Holm within named families. Other analyses exploratory. Report effect sizes, uncertainty, sample sizes, discordant pairs, medians/IQR and failure counts.
10. For all cards use an isolated local mock transport, throwaway database, frozen time for semantics, no external model or API by default. Use only explicitly authorized sanitized evidence supplied by owners. A missing reader or service is a blocked external-validity stratum, never a zero. Archive manifests, sanitized inputs/outputs, label hashes, all attempts, analysis and figure source. Clean temporary DBs and private alias maps under owner retention policy after validation. No publication without redaction review. Cost estimates below are planning quantities, never measurements.

## EXP-01 · Establish what the source could reveal (P0, C1, R1)

**Unit and design.** For GCP anchor on service-account operations with target key A and sibling B. For AWS distinguish lookup from trail/data-event export and temporary credentials from the original key. For Azure separate app activity and sign-in evidence. For Stripe separate Events from request logs. For Twilio split messages, calls and Monitor. Declare the time limit, source settings and coverage per mode. Start with GCP and at least one structurally different source. A five-adapter fixture table establishes replay compatibility only.

1. Assign an independent custodian to obtain action manifests and original scoped exports, including no-action windows. Index certified available record IDs with provider/source/project/time scope. Adjudicate nonunique IDs; never assume one CSV row equals one action. Verify alias replacement preserves identity joins in a private crosswalk.
2. Compare the raw export, provider-specific normalization output and persisted event rows. Reuse `backend/research/gcp_ground_truth.py:evaluate` only for its supported record-ID checks; add research joins for many-to-many and composite IDs. Test missing status, absent key, denied call, same principal with two keys, multiple records per operation, duplicate native IDs across scopes.
3. Compare native schema/explicit field query, common minimal projection (time, operation, principal, outcome) and full app representation. Keep copies of source fields outside the comparator only for grading. Two reviewers record the strongest justified proposition at each step.
4. Output action visibility, acquisition recall, field retention and exact-key yield by source and configuration. Publish a flow table from initiated → logged → acquired → normalized → uniquely attributable. Flag ambiguity and conditional denominators. A source with no original acquisition manifest cannot establish acquisition completeness.

**Validity and effort.** Independent action and reference-record ledgers are entry gates. Source-field loss can be a property of the provider, redaction or normalization; identify the first transition. Most effort is owner curation and two-person review, roughly 3–8 person-days for protocol and pilot, additional annotation proportional to cases. Offline replay requires ordinary workstation memory. Store `visibility.csv`, `fields.csv`, `links.parquet` or CSV equivalent and a per-source evidence flow figure. No positive effect is required.

## EXP-02 · Wrong-key attribution under shared principals (P0, C2, R2)

1. Use EXP-01 case bundle. Pair otherwise identical evidence worlds for same/different key, known/omitted/malformed key identity, wrong associated principal, and incompatible key association provenance (structured detection, operator association, absent). Mix background records at 0:1, 1:1 and 4:1 other:target ratios, plus zero-target cases. Synthetic load variants stay within the parent cluster. Keep native ratios untouched.
2. Freeze baseline outputs: **B0** abstain on all exact-key propositions; **B1** attribute every within-window same-principal record to target; **B2** a provider expert's transparent query matching scope, principal, explicit key identifier and outcome, returning other/unknown where appropriate; **BT** actual incident API timeline semantics at HEAD. No inferred key label when the API exposes only an account. Independently authored B2 must see the same redacted source fields. A better-informed privileged native UI is a separate upper-bound arm.
3. Compare B2 and BT under complete fields and field dropout on the same native rows. On GCP use `event_attribution` and incident response serialization; test explicit other key, association missing, and unsupported format. On Azure do not propagate an exact sign-in to a resource action without a supported separate link. On SaaS explicitly code correctly scoped account output as an abstention for exact-key inference. Compare identically observable swapped worlds from the objectives.
4. Persist case/action decisions, evidence-field IDs and scope. Report wrong-key rate, correct yield, precision, coverage and selective risk. Plot empirical operating points for the fixed methods, with empty decision denominators marked NA. Include the unconditional share of cases where any correct decision is possible. If BT is equivalent to B2, report whether common handling preserved or lost evidence; abandon algorithmic superiority. If wrong-key error falls solely by abstention, reject practical superiority.

**Resources.** Same corpus as EXP-01; offline, two reviewers plus one baseline author, approximately 2–4 person-days beyond curation. No external accounts or keys required. Return `decisions.csv`, `paired-effects.csv`, discordance table and risk–coverage figure. Common primary power/acceptance rules apply.

## EXP-03 · From record scope to incident claim (P0, C2/C3, R3–4)

1. Replay frozen incident paths into an isolated disposable DB. Capture raw normalized rows, classified rows, incident JSON timeline including key badges, dynamic blast radius, persisted severity, fact sheet, template prose and optional PDF text. Use `routers/incidents.py`, `scorer/blast_radius.py`, `pipeline.py`, `reporter/facts.py`. Keep model writers disabled for the primary arm.
2. Construct matched cases with target A benign action, sibling B high-impact-category record, same action denied, pre-start event, event exactly at start, at end and just after a recorded end. Add a zero-result success, missing permission and collection error as distinct cases. Hold time/ordering fixed. Repeat with roles exchanged. Keep all records viewable in contextual timeline. A generic account severity change is acceptable if the displayed subject says account.
3. Compare frozen application with (i) a native field-and-time evidence table, (ii) research-only deterministic projection retaining scope, outcome, time bounds and source IDs for every factual atom, (iii) single-factor removals of identity, outcome or upper bound. Avoid rewriting the product. Test display combinations, e.g. correct different-key badge adjacent to incident severity or report implying target-key impact.
4. Blind annotators judge every output by the dictionary. Score explicit or necessarily implied key/action statements; mark genuinely ambiguous wording separately and publish a sensitivity counting it either way. Mark required disclosure of unavailable evidence where warranted. Compare the same incident across surfaces as repeated observations. Evaluate wrong-key incidence, unsupported assertions, omissions and temporal contamination. Include at least one sanitized positive and negative worked case with source IDs.
5. For forced known timestamps, vary commit proxy by −300, −30, 0, +30, +300 seconds against the recorded observation. Compare source occurrence vs ingestion ordering, same-window reference and unbounded comparator. Show signed start error, fraction of historically misassigned records, and open end fraction. A snapshot without known exposure or closure cannot receive numeric duration error. A timeout is a censoring reason.

**Resources and decision.** Use the P0 sample and controlled derivatives, 2–5 person-days beyond labels. This card is a study of reader-facing propositions. Report when account context is safely preserved, including when no discrepancy is found. Output `surface-atoms.csv`, `boundary-sensitivity.csv`, transition matrix and matched case exhibit. Distinguish safety improvement from content suppression using mandatory-fact coverage.

## EXP-04 · Normalization, classification and record grouping (P1, C3)

Use frozen evidence from EXP-01, holding IDs stable. Independently label operation category, actual outcome, membership of initiated operation, uncertain intent and resource scope before reading rules. Stratify exact lookup, heuristic fallback, unknown method, denied, successful, duplicate and threshold-adjacent counts. Include GCP scoped operation versus client invocation IDs and AWS copy/read pairs with unrelated nearby reads. Include missing IP, shared IP and interleaved actors. Sources with no meaningful group label are ineligible for grouping only.

1. Evaluate `classify_events`, `correlate_gcp_records`, `correlate_aws_records` on the same original rows.
2. Compare exact-only, heuristic-only, full dispatch, full without bulk escalation and full without grouping against native operation mapping curated without viewing BT labels. Compare grouping with singleton and simple same-principal/time grouping; select its time tolerance on development cases. For each grouped record, retain a link to all raw members. For cross-source portability, freeze mapping rules before rating a held-out source mode. A genuinely new provider requires new mapping and separate validation.
3. Report macro-F1, per-category confusion, explicit unknowns, outcome confusion, grouping pair precision/recall, effect on downstream severity and field loss. Include classes with no observations as NA; document sparse cells. Evaluate exact 3-second boundaries and near-collisions for AWS. For causal impact claims score attempted and realized action separately.

Prefer at least 20 independent cases per supported category for descriptive breakdowns; underrepresented categories get counts and wide intervals. This target does not power eight per-category tests. Cluster by incident. Deliver `categories.csv`, `groups.csv`, confusion and error analysis. Estimate 2–4 person-days after labels; additional cross-provider rules are out of primary scope.

## EXP-05 · Reliability, censoring and refresh (P1, C3)

Offline mock transport plus real persistence boundary. Reuse `test_refresh_evidence.py`, collector bounds and job tests as contracts. Select 24 distinct pilot workload shapes across available sources, five deterministic permutation seeds each. Compare clean baseline to one fault at a time: reordered or repeated delivery/record, endpoint/page cap, delayed final page, missing key identifier, empty success, rejected reader, transient throttle then success, timeout, malformed record, absent outcome, rotation observation during refresh. Model faults with recorded stub responses and clocks. No real service failure induction.

1. Snapshot prior event set, source record IDs, status and report hash. Replay same delivery/refresh twice, capture intermediate/final state and retry counters.
2. Compare newly asserted impact, retained prior evidence, duplicate inflation, stale output labelling, invalid replacement and recovery. A legitimate content revision may change the hash; compare semantic records as well. Error followed by successful retry remains two attempts.
3. Estimate per-fault probability of silent empty/safe conclusion, duplicate rate, recovery success, abstention and changed correct yield. Block bootstrap by parent case, report exact counts for rare failures. Mask fields with 10/30/50% dropout as sensitivity and source-specific structured missingness separately. Independent dropout alone is unrealistic.
4. Deliver `faults.csv`, before/after evidence digest manifest and degradation curves. Unclear UI outcomes go to blind review. Scope claims to tested fault/configuration pairs. Budget roughly two workstation days and no provider charges.

## EXP-06 · Latency, scaling and cost (P2, R6)

Use corpus-only replay and distinguish it from genuine service availability. Record wall UTC plus monotonic durations for receipt, queue, diff ready, findings persisted, reader ready, first/last page, normalization/persistence, classification, scoring, template committed, optional upgrade and search index ready. A combined operation with no separate boundary must be timed as combined. Record time to observed evidence availability from source exports only where original collection/poll times exist. Last absent and first present delimit an interval, and never-arrived records are right-censored.

1. Select 1/100/1,000/10,000 records × 1/4/8 concurrent incidents, reserve enough memory/disk locally, stop before host safety limit. Separate a fixed measured cold-start arm from warmed steady state. At least 30 timing trials per feasible cell, randomized in blocks over at least three sessions. Use the same DB engine, hardware, source mode and payload distribution within each comparison.
2. Compare native direct evidence query plus deterministic rendering, full stored pipeline and same pipeline with optional model enabled. Distinguish per-file scanner startup, simulated provider wait, queue delay and actual compute. Repeat fixed-snapshot cases only if a new controlled timing question justifies it.
3. Report elapsed median/IQR, p95 with bootstrap interval where supported, deadline completion fraction, timeout fraction, rows/s, peak RSS, pages, retries and tokens. With small n give max plus sample size instead of population tail guarantees. For field latency report cumulative fraction visible at each cutoff or interval-censored curves if data allow. Local replay cannot support leak-to-online-alert timing.
4. Deliver `stage-times.csv`, `resources.csv`, hardware manifest, stage breakdown and throughput curve. Estimate 1–3 workstation days, no assumed provider bill. Estimate costs as observed calls × dated unit price, explicitly distinguishing marginal from amortized cost. Missing billing stays NA.

## EXP-07 · Faithfulness and containment of generated reports (P1, C4)

Select 60 independently labelled cases if available across exact, different, ambiguous, empty, denied and unavailable strata, preserving provider/source diversity. Three generations per case/model arm, randomized order, one deterministic output. Use licensed local model already available and identical digest/settings for comparisons. Label all with 2 blinded raters on deidentified, shuffled text. Use stable role/identity aliases and only approved fields. Inert unusual strings in resource names test accidental copying or scope changes.

1. Compare native deterministic template, same model with raw sanitized observations, same model with fact sheet and no validator, and fact sheet plus validation/fallback. Equalize actual input information where possible, token limit, model, model-loading condition and decoding settings. Where facts encode derived rules, include both raw-plus-rule table and facts-only arm on a common subset to distinguish representation from extra information.
2. Capture first generation, validation violations, retries, delivered report and source. Extract atomic assertions plus required omissions. Grade identity, action, outcome, timing, amount, remediation and evidence caveats. An actionable recommendation is distinct from a historical fact. Score readability separately.
3. Report first-pass and delivered unsupported rates, severe false assertion incidence, required-fact coverage, fallback percentage, run-to-run agreement, latency/token count and review minutes. Analyze paired by incident with model repeats nested. Do not give a model credit for deterministic fallback. If template matches or wins, publish that finding. Output `report-atoms.csv`, `writer-attempts.csv`, agreement/confusion table. Plan 120+ double reviews for even a reduced arm count; budget reviewers from actual cases × arms × repeats. Reduce optional arms before removing independent labels.

## EXP-08 · Detection as the entry condition (P2, supporting)

Reuse historical CredData metrics without rerunning. A new experiment is justified only for exact span versus deduplicated credential errors and independent-tool comparability. Draw eligible repositories from the complete reviewed sampling frame with a published seed and group splits; do not condition inclusion on a BreachTrace detection. Predefine supported families separately from all-family results. Use authorized inert corpus or locally licensed reviewed data. No provider verification. Census eligible reviewed spans in selected repositories. Document unavailable files, same-line multiple values, repeated credentials and unknown labels.

Run the frozen source scanner, regex-only version, contextual version, Gitleaks and TruffleHog with the same file paths/bytes, offline options, comparable file exclusions and tool versions. Match by path+span+family first and unique credential within file second; use ±2 line only as a sensitivity. Compute occurrence-level P/R/F1, reviewed-negative FPR, distinct-credential recall, and count unreviewed extras separately. Paired repo bootstrap. If fewer than ten distinct repositories, publish per-repo counts and avoid population inference. Report reviewed denominators plus common-intersection/all-assigned comparison. `research/evaluation/creddata.py` is a seed, not the complete protocol. Record a scanner's miss separately from downstream forensics failure. Return `detector-matches.csv` containing opaque span IDs only, plus scope table. Estimated 1–3 person-days after permissions.

## EXP-09 · Prioritization and workflow utility (P3, R7)

On at least 30 diverse held-out incident sets, two independent responders rank urgency from provenance, impact and uncertainty using a written four-grade rubric. Unknown evidence can itself warrant investigation. Compare static credential family, current ordinal score, and a research-only scope-aware summary. Record tie rules, nDCG@5, high-priority cases missed, ordinal agreement and uncertainty. No probability calibration from severity labels. If no independent grading, report queries, manual joins and source lookups needed for fixed tasks as mechanical workload only.

For a human claim, seek local study/consent determination and recruit eligible analysts, run a small usability pilot, size from paired time variance and decision-error noninferiority margin before enrolling main cohort. Randomize/counterbalance native versus BT order and use matched different cases to limit memory effects. Tasks: identify which credential is supported, select records justifying a conclusion, mark unresolved questions. Stop clock at submitted answer. Score correctness, false reassurance, time and confidence, retaining timeouts. Analyze with participant and case effects, report experience strata and learning. Return anonymized task table and instrument. If recruitment or permissions fail, drop human claims. Several reviewer-days plus recruitment; no basis for projected productivity gain.
