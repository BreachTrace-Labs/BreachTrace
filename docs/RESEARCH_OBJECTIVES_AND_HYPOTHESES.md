# Objectives, estimands and hypotheses

**Main objective.** Quantify the accuracy and useful coverage of credential-specific conclusions given a repository observation and a bounded audit source. Identify whether failures arise in source visibility, evidence acquisition, normalization, attribution, aggregation or presentation. The population is owner-authorized case bundles in the sampled configurations. Extrapolation to all public leaks, providers or human adversaries needs new data.

## Units and ground truth

An incident i identifies one repository observation and a target credential alias k. A ledger contains initiated operations a, their credential alias, actor role, resource alias, result and trusted time interval. An independently archived source contains records r. The adjudicated relation M(a,r) is many-to-many, with unresolved edges retained. A proposition c specifies subject, operation, object, outcome, time interval and strength. A report may say an account recorded activity, this particular credential authenticated, this credential performed an operation, or a person caused harm. Those propositions require different evidence.

Annotate two independent axes: **what happened** according to the held-back ledger and **what the observed evidence warrants** according to blind reviewers of the same inputs as the system. An exact-key statement can be accidentally true and evidentially unsupported. A different-key record can support a positive contradiction. Retain absence, contradiction and insufficient information as distinct states. Authentication and resource activity have different predicates. For actor intent use authorized, scenario-labelled concerning, or indeterminate. Logs alone cannot establish intent.

A simple identifiability control uses two worlds. Swap keys A and B behind one principal while holding all exposed principal-only fields constant, including action, resource and time. If the observation is identical, a deterministic estimator must give the same answer in both worlds. With equiprobable worlds a forced choice has at most 1/2 accuracy for that pair. This is an analytical construction, not a measured prevalence or performance bound for arbitrary workloads. An independent key-bearing field can break the equivalence. Register source modes where the construction is valid.

## Metric dictionary

* **Action visibility** = distinct initiated actions with ≥1 independently matched source record / eligible initiated actions. **Acquisition recall** = unique reference records acquired / reference records available within the cutoff and scope. **Normalization retention** = values preserved with correct semantics / applicable populated native values, by field. For many-to-many links count distinct IDs; publish an unmatched/ambiguous category.
* **Wrong-key assertion rate** = non-target actions explicitly assigned to target / all ledger non-target actions. **Selective error** = wrong exact-key assignments / all exact-key assignments. **Coverage** = actions receiving a definite identity decision / eligible actions. **Correct target yield** = distinct target actions correctly and evidentially identified / initiated target actions. Also report exact-positive precision and recall conditional on acquired evidence. Always publish denominators and abstention.
* **Unsupported-claim incidence** = incidents with ≥1 unsupported or contradicted identity/outcome assertion / eligible incidents. **Unsupported fraction** = unsupported or contradicted atoms / emitted factual atoms. For empty prose report omission and output failure separately. **Required-fact coverage** = supported mandatory atoms conveyed / preregistered applicable mandatory atoms. Qualify an uncertain statement by scoring its actual modality.
* **Temporal contamination** = out-of-interval records included as impact / included impact records. **Boundary error** = signed proxy minus known timestamp for observable endpoints. Use interval inclusion for imprecise clocks, censor unobserved endpoints. **Pairwise grouping precision/recall** = correct grouped same-operation record pairs / predicted or true pairs respectively. No group predicted gives undefined precision.
* **Category accuracy** reports per-category confusion and macro-F1 across declared supported categories, with unknown as a prediction. Report outcome (attempt, denied, successful, unknown) separately. **Ranking** uses nDCG@5 with independent graded relevance plus high-priority misses, ties reported. Thresholds are ordinal. Probability calibration needs held-out probabilistic predictions and true binary outcomes.
* **Operational measures** include seconds per stage on monotonic clocks, request pages/retries, incident completions per second, peak process RSS in MiB, tokens and measured billed/allocated cost with currency/date/unit. A zero count, unsuccessful query, unavailable configuration and undefined ratio must remain distinguishable.

Use equal incident weights for primary paired case effects and disclose pooled event-weighted sensitivity. Report results by provider/source before aggregation. Different native fields can change the meaning of the same-looking metric. Design and practical thresholds appear in MASTER_EXPERIMENTAL_PLAN.md.
