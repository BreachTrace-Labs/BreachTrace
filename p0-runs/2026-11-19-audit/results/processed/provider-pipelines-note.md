# Azure, Stripe and Twilio pipeline fixtures

One synthetic event per provider was mapped and passed through the frozen pipeline with collection stubbed, then the actual incident detail route was called. All three completed and saved deterministic reports. Azure had Low severity, Stripe Critical and Twilio Medium, using the application's scoring rules on these individual fixtures. The amounts and action labels are constructed inputs and generated classifications, not real loss or proof of abuse.

The Azure report described Activity Log as application identity evidence, not a particular client secret; the Stripe report described Events as account activity, not key attribution; the Twilio report said Messages and Calls are account activity, not proof of use by a particular key. These are observations of wording, not independently adjudicated assertions. Each contains one case only. Native acquisition, independent action truth, field dropout, negative controls and blinded review remain outstanding.

A second process and fresh in-memory database reproduced the selected semantic surfaces using the same checkout and virtual environment; the recorded check excludes generated IDs and the timeline.
